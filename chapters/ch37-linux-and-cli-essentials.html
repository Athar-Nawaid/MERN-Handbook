1. The Linux Filesystem Hierarchy & Core Philosophy

Linux is founded on the Unix philosophy: "Everything is a file." Hardware devices, network sockets, physical disks, and kernel process metrics are all exposed as file streams in the virtual filesystem.

Directory Standard Purpose & Full-Stack Significance
/etc System-wide configuration files (e.g., /etc/nginx/nginx.conf, /etc/hosts, /etc/systemd/system/).
/var/log Persistent system and application log files (e.g., /var/log/nginx/access.log, /var/log/syslog).
/proc Virtual filesystem generated in memory by the Linux kernel; contains real-time runtime state for processes (e.g., /proc/cpuinfo, /proc/meminfo, /proc/[pid]/).
/tmp Temporary files accessible by all users; wiped on reboot. Protected by the Sticky Bit.
/dev Device nodes representing hardware and pseudo-devices (e.g., /dev/null black hole, /dev/urandom cryptographically secure random bytes).
/usr/bin Standard user executable command binaries (e.g., node, npm, git, curl).

2. File Permissions & Octal Arithmetic

Every file and directory in Linux has an ownership tuple: a User Owner, a Group Owner, and permissions for Others.

ASCII Diagram: Linux File Permission Triad 
  File Type: '-' = file, 'd' = directory, 'l' = symlink
  |
  |  [User Owner]    [Group Owner]    [Others (World)]
  |    r  w  x         r  -  x         r  -  -
  v   (4+ 2+ 1)       (4+ 0+ 1)       (4+ 0+ 0)
  -      7               5               4        --> Octal: 754

  r (Read)    = 4 : View file content / List directory entries
  w (Write)   = 2 : Modify file content / Create or delete files in directory
  x (Execute) = 1 : Execute binary/script / 'cd' into directory

Standard Production Permission Presets

  • chmod 644 file.txt: Owner can read/write; Group and Others can only read. (Default for web files, source code).
  • chmod 755 script.sh: Owner can read/write/execute; Group and Others can read/execute. (Default for directories and executables).
  • chmod 600 id_ed25519: Owner can read/write; zero access for Group and Others. (Mandatory for private SSH keys; SSH clients refuse keys with looser permissions!).
  • chmod 700 ~/.ssh: Owner can read/write/cd; completely private. (Standard for SSH configuration directories).

3. Process Management: States, Signals, and Systemd

Every process in Linux is assigned a unique PID (Process ID). The root ancestor of all user-space processes is PID 1 (typically systemd in modern Linux distributions).

Process State Indicator Code Operating System State & Meaning
Running / Runnable R Actively executing on CPU or waiting in the scheduler CPU run queue.
Interruptible Sleep S Waiting for an event or I/O (e.g., Node.js event loop waiting for incoming network connections). Responds to signals.
Uninterruptible Sleep D Waiting on direct hardware disk or NFS I/O. Cannot be killed by any signal, including kill -9!
Zombie Z Terminated execution, but its parent process has not yet read its exit code via the wait() system call. Consumes no CPU/RAM, but consumes a PID slot.

Signals: Terminating and Reloading Processes

  • kill -15 <PID> (SIGTERM - Default): Politely requests the process to terminate. The process can catch this signal to close database connections, finish in-flight HTTP requests, and execute graceful shutdown logic.
  • kill -9 <PID> (SIGKILL): Handled directly by the Linux kernel; instantly terminates the process. The process cannot catch or ignore SIGKILL. Leaves open file locks and unfinished transactions; use only as a last resort.
  • kill -1 <PID> (SIGHUP): Hangup signal. Conventionally used by daemons like Nginx to reload configuration files without dropping active connections.

Production Systemd Service Unit

In cloud environments without Docker, Node.js applications are managed via systemd service units to ensure automatic boot restart, environment variable injection, and non-root execution:

INI: /etc/systemd/system/myapp.service 
[Unit]
Description=Production Node.js API Service
After=network.target postgresql.service

[Service]
Type=simple
User=node
WorkingDirectory=/var/www/myapp
ExecStart=/usr/bin/node dist/server.js
Restart=always
RestartSec=5
Environment=NODE_ENV=production PORT=3000
EnvironmentFile=/etc/myapp/.env

# Security Sandbox Hardening
ProtectSystem=full
NoNewPrivileges=true

[Install]
WantedBy=multi-user.target

4. Standard Streams, Redirection, and Piping

Every Linux process opens three standard file descriptors:

  • stdin (FD 0): Standard input (keyboard or piped data).
  • stdout (FD 1): Standard output (terminal display).
  • stderr (FD 2): Standard error (error logging).
Bash: Redirection and Piping Patterns 
# Overwrite stdout to a file
node app.js > output.log

# Append stdout to a file
node app.js >> output.log

# Redirect stderr only to error.log
node app.js 2> error.log

# Combine stdout AND stderr into the same file
node app.js > app.log 2>&1

# Discard all output completely (silent run)
node app.js > /dev/null 2>&1

# Piping: output of command A becomes input of command B
cat /var/log/nginx/access.log | grep " 500 " | wc -l

5. The Log Analysis Toolkit: grep, awk, and sed

When an incident occurs in production, senior engineers rely on command-line text stream processing tools to extract insights from massive gigabyte log files in seconds without opening slow text editors:

Tool Core Capability Essential Production Command Example
tail Output the last part of files; follow live stream. tail -f -n 100 /var/log/nginx/error.log (Stream live errors in real time).
grep Pattern search using regular expressions. grep -rn "Database connection timeout" /var/log/app/ (Recursive search with line numbers).
awk Column-oriented pattern scanning and processing language. awk '$9 >= 500 { print $1, $7, $9 }' access.log (Prints IP, path, and status code for all 5xx errors).
sed Stream editor for filtering and transforming text. sed -i 's/OLD_HOST/NEW_HOST/g' config.env (In-place global find-and-replace).
sort & uniq Sort lines and report duplicate counts. sort | uniq -c | sort -nr (Count and rank occurrences descending).

6. Networking Diagnostics: ss, lsof, and curl

Finding Which Process Owns a Port

A frequent local and production error is: Error: listen EADDRINUSE: address already in use :::3000.

Bash: Diagnosing and Freeing Blocked Ports 
# Method 1: Using lsof (List Open Files)
lsof -i :3000
# Output:
# COMMAND   PID USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
# node    14520 alex   22u  IPv6 123456      0t0  TCP *:3000 (LISTEN)

# Kill the rogue process holding port 3000:
kill -15 14520

# Method 2: Using ss (Socket Statistics - modern netstat replacement)
ss -tulpn | grep :3000
# -t = TCP, -u = UDP, -l = listening, -p = show process, -n = numeric ports

API Testing with curl

Bash: Production curl Diagnostic Commands 
# Inspect HTTP response headers only (-I)
curl -I https://api.myapp.com/healthz

# Measure total latency Breakdown (-w)
curl -o /dev/null -s -w "DNS: %{time_namelookup}s | Connect: %{time_connect}s | TTFB: %{time_starttransfer}s | Total: %{time_total}s\n" https://api.myapp.com

# Send POST JSON payload
curl -X POST https://api.myapp.com/v1/orders \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer secret_token" \
  -d '{"items":[{"id":"p1","qty":2}]}'

7. System Resources & Load Averages

Running uptime displays three load average numbers: load average: 2.10, 1.45, 0.85. These represent the average number of processes in the Runnable (R) or Uninterruptible Sleep (D) state over the last 1, 5, and 15 minutes.

💡 How to Interpret Load Average Relative to CPU Cores

A load average must always be evaluated relative to the server’s total CPU core count (found via nproc):

  • On a 4-core server: A load of 4.00 means 100% capacity utilization. Every core is fully saturated, but no processes are waiting.
  • A load of 8.00 on 4 cores means the system is overloaded by 100%: for every process running, another process is waiting for CPU time!
  • A high load average accompanied by low CPU usage indicates an I/O bottleneck: processes are stuck in state D waiting on slow disks or network file storage.

8. Practical Exercises

Exercise 1: Top 10 IP Addresses Causing 500 Errors Pipeline

Scenario: You are investigating an ongoing incident. Construct a bash one-liner that parses an Nginx access log (format: $remote_addr - - [$time] "$request" $status ...), extracts client IPs for all requests with status code 500, counts occurrences, and prints the top 5 offending IPs.

View Complete Solution
Bash One-Liner 
# In standard Nginx logs: Column 1 is IP, Column 9 is HTTP status
awk '$9 == 500 { print $1 }' /var/log/nginx/access.log | sort | uniq -c | sort -nr | head -n 5

# Explanation:
# 1. awk filters rows where status ($9) is 500 and prints the client IP ($1)
# 2. sort prepares identical IPs for grouping
# 3. uniq -c collapses duplicates and prefixes each line with its frequency count
# 4. sort -nr sorts numerically descending
# 5. head -n 5 limits output to the top 5 worst offenders

Exercise 2: SSH Port Forwarding Tunnel

Scenario: A production PostgreSQL database is locked inside an AWS private VPC subnet without public internet access. You have SSH bastion server access (bastion.myapp.com) on port 22. Write the command to tunnel your local port 5433 to the private database db.internal:5432 through the bastion.

View Complete Solution
Bash Command 
# Local port forwarding syntax: ssh -L [local_port]:[target_host]:[target_port] [user]@[bastion]
ssh -N -L 5433:db.internal:5432 ubuntu@bastion.myapp.com -i ~/.ssh/id_ed25519

# Flags:
# -N = Do not execute a remote command (port forwarding only)
# -L = Local port forward
# Now you can connect to localhost:5433 using pgAdmin or psql!

9. Chapter-Specific Interview Questions & Answers

20 high-frequency interview questions covering Linux file permissions, process states, signals, log parsing, networking CLI, and system resource troubleshooting.

Q01 What does the permission octal 755 mean on a Linux file or directory? Beginner
Spoken Interview Answer

"In 755: the first digit (7 = 4+2+1) grants the user owner Read, Write, and Execute permissions. The second digit (5 = 4+0+1) grants members of the file's group Read and Execute permissions. The third digit (5 = 4+0+1) grants all other users Read and Execute permissions. It is the standard permission setting for directories and public executables."

Q02 What is the difference between kill -9 (SIGKILL) and kill -15 (SIGTERM)? Beginner
Spoken Interview Answer

"SIGTERM (15) is a graceful termination request: the process can catch this signal to finish active HTTP requests, flush buffers, close database connections, and shut down cleanly. SIGKILL (9) is handled directly by the Linux kernel and terminates the process immediately without notification; the process cannot intercept or handle SIGKILL."

Q03 How do you find which process is currently listening on port 3000? Beginner
Spoken Interview Answer

"I use `lsof -i :3000` or `ss -tulpn | grep :3000`. Both commands display the Process Name, User, and the exact PID listening on the socket, allowing you to gracefully terminate it using `kill `."

Q04 What does 2>&1 mean in Linux command redirection? Beginner
Spoken Interview Answer

"It redirects Standard Error (file descriptor 2) to the same destination as Standard Output (file descriptor 1). When placed after `> output.log`, both regular console logs and error streams are merged into the same log file."

Q05 What is the difference between piping (|) and redirection (>)? Beginner
Spoken Interview Answer

"Redirection (`>`) takes the output stream of a command and writes it to a file or device. Piping (`|`) connects the Standard Output of one command directly to the Standard Input of another command in memory via a kernel buffer, enabling command chaining without creating intermediate temporary files."

Q06 What is a Zombie Process in Linux and how do you resolve it? Intermediate
Spoken Interview Answer

"A Zombie process (state `Z`) has completed execution, but its parent process has not yet reaped its exit status using the `wait()` system call. Zombies consume no CPU or memory, but consume a slot in the operating system process table. You cannot kill a zombie with `kill -9` because it is already dead; you must kill its parent process or restart the parent so PID 1 adopts and reaps it."

Q07 How do you interpret Load Average values (e.g. 1.0, 5.0, 15.0) on uptime? Intermediate
Spoken Interview Answer

"Load average represents the average number of processes in the runnable state (`R`) or uninterruptible sleep state (`D`) over 1, 5, and 15-minute intervals. It must be compared against the number of CPU cores (`nproc`). On a 4-core machine, a load of 4.0 indicates 100% saturation. A load of 8.0 indicates 100% overload with tasks queuing for CPU time."

Q08 What is the difference between buffer and cache in the free -m command? Intermediate
Spoken Interview Answer

"Buffers store raw block device metadata waiting to be written to disk. Page Cache caches recently read and written file data in unused RAM to accelerate future disk reads. Linux uses available RAM aggressively for page caching, but instantly releases it to applications when memory is demanded. A system showing low 'free' memory but high 'available' memory is completely healthy."

Q09 What is the Sticky Bit on Linux directories and where is it used? Intermediate
Spoken Interview Answer

"The Sticky Bit (indicated by a `t` in permissions, e.g. `drwxrwxrwt`) restricts file deletion within a shared directory. In directories like `/tmp` where all users have write permissions, the sticky bit prevents one user from deleting or renaming files owned by another user. Only the file owner, the directory owner, or root can delete the file."

Q10 Why must private SSH keys have file permissions set to 600? Intermediate
Spoken Interview Answer

"`chmod 600` ensures that only the file owner has read and write permissions, preventing other local users or compromised processes on the system from reading your private key. OpenSSH clients enforce this security check strictly: if a private key has permissions accessible by group or others (like `644`), SSH will refuse to use the key and abort the connection."

Q11 How do you stream and filter live production logs for specific keywords? Intermediate
Spoken Interview Answer

"Use `tail -f /var/log/app/server.log | grep --line-buffered -i 'error\\|fatal\\|exception'`. The `--line-buffered` flag ensures that grep flushes matched lines immediately to the console rather than buffering them in memory, allowing real-time monitoring of production anomalies."

Q12 What is the difference between df -h and du -sh? Intermediate
Spoken Interview Answer

"`df -h` (Disk Free) inspects mounted filesystems from the superblock, reporting total capacity, used space, and percentage free across disk partitions. `du -sh` (Disk Usage) recursively scans specific directories or files, calculating the exact byte space consumed by that specific directory tree on disk."

Q13 How do you run a Node.js process in the background and keep it running after logging out? Intermediate
Spoken Interview Answer

"For quick ad-hoc jobs, use `nohup node server.js > app.log 2>&1 &`. `nohup` ignores the SIGHUP signal sent when the SSH terminal closes, and `&` puts the process into the background. For production, however, always manage processes via a system supervisor like `systemd` or PM2 to ensure auto-restart on crashes."

Q14 What is Time To First Byte (TTFB) and how do you measure it with curl? Intermediate
Spoken Interview Answer

"TTFB measures the duration from when the client dispatches the request until the first byte of response data arrives from the server, indicating server processing and network latency. We measure it using: `curl -o /dev/null -s -w '%{time_starttransfer}\\n' https://api.myapp.com`."

Q15 What does the process state 'D' (Uninterruptible Sleep) mean and why is it dangerous? Advanced
Spoken Interview Answer

"State 'D' means the process is waiting on kernel device driver I/O—typically physical disk access, slow NFS mounts, or corrupted hardware. The kernel blocks all signal delivery to processes in state D to prevent filesystem corruption; thus, even `kill -9` cannot terminate them. If many processes pile up in state D, load average skyrockets and the server may require a hardware reboot."

Q16 Why can a deleted log file still consume disk space according to df -h? Advanced
Spoken Interview Answer

"In Linux, removing a file unlinks its directory entry, but the inode and data blocks are only freed when all open file descriptors referencing that file are closed. If an active process (like Node.js or Nginx) continues holding an open handle to `access.log`, the disk blocks remain allocated. Running `lsof | grep deleted` identifies the process; restarting or reloading the process frees the disk space."

Q17 What is SSH Local Port Forwarding vs Remote Port Forwarding? Advanced
Spoken Interview Answer

"Local Port Forwarding (`ssh -L 8080:internal.db:5432 user@bastion`) opens a listening port on your local machine and tunnels traffic through SSH to access a private remote service. Remote Port Forwarding (`ssh -R 9000:localhost:3000 user@server`) opens a port on the remote server and tunnels incoming remote connections back to your local development machine (useful for testing external webhooks)."

Q18 How does Linux Page Cache accelerate web server performance? Advanced
Spoken Interview Answer

"When Nginx serves static HTML, images, or assets, the Linux kernel copies those files from disk into the RAM Page Cache. Subsequent requests for those files read directly from RAM at gigabytes per second with zero disk I/O. Furthermore, system calls like `sendfile()` transfer data directly from the kernel Page Cache to the network socket descriptor without copying bytes to user-space memory."

Q19 What is the difference between hard links and soft (symbolic) links? Advanced
Spoken Interview Answer

"A Hard Link is an additional directory entry pointing directly to the exact same underlying inode on the filesystem; deleting the original file keeps the data intact as long as one hard link remains. A Symbolic Link (symlink, `ln -s`) is a special pointer file containing the text path to another file; if the target file is deleted or moved, the symlink becomes broken."

Q20 How do you triage a production Linux server that is completely unresponsive to SSH? Intermediate
Spoken Interview Answer

"First, check cloud console metrics (AWS EC2 / GCP) to see if CPU is at 100%, memory is exhausted (triggering kernel OOM panic), or disk I/O is saturated. If the cloud serial console or Out-of-Band management is accessible, check kernel ring buffer messages (`dmesg`). If totally frozen due to thrashing, execute a hard instance reboot from the cloud console and inspect `/var/log/syslog` post-recovery."
