1. Semantic HTML and Accessibility (a11y)

Semantic HTML means using HTML markup to reinforce the meaning of the information in web pages, rather than merely defining its visual appearance.

Semantic Landmark Tag Architectural Purpose Screen Reader & SEO Impact
<header> Introductory content, site branding, navigational bar. Identified as landmark banner; aids quick keyboard navigation.
<nav> Major navigation blocks linking to pages or internal sections. Screen readers allow users to jump directly past or into navigation.
<main> Dominant, central content unique to this document. Exactly one per document. Users can skip repetitive headers directly to main.
<article> Self-contained, reusable composition (blog post, product card, forum comment). Can be distributed independently via RSS feeds and news aggregators.
<section> Generic standalone thematic section of a document. Should typically begin with a heading tag (<h2>).
<aside> Content tangentially related to the surrounding content (sidebar, callout). Screen readers can skip aside content when reading main flow.
<button> vs <div onclick> Interactive trigger for actions. Native keyboard focusable (Tab), triggers on Space and Enter, exposes button role.
⚠️ The Anti-Pattern: "Div Soup"

Replacing buttons with <div class="btn" onclick="..."> breaks accessibility! A div cannot be focused via the Tab key, does not respond to Enter or Space, and is completely invisible to screen readers unless you manually add tabindex="0", role="button", and keyboard event handlers. Always use native <button> elements for actions and <a href="..."> for page navigations!

2. CSS Specificity and the Box Model

The Specificity Calculation Matrix

When multiple conflicting CSS rules target the same element, the browser calculates a 4-column specificity tuple (Inline, ID, Class, Element):

  • Inline Styles (1, 0, 0, 0): Styles applied directly on the HTML element via style="...".
  • IDs (0, 1, 0, 0): Selectors targeting an ID, e.g., #navbar.
  • Classes, Attributes, and Pseudo-classes (0, 0, 1, 0): E.g., .btn, [type="text"], :hover, :focus.
  • Elements and Pseudo-elements (0, 0, 0, 1): E.g., div, p, ::before, ::after.
  • Universal selector (*) and combinators (+, >, ~): Specificity of (0, 0, 0, 0).
  • !important: Overrides the standard specificity hierarchy completely.
Selector: #main-nav .menu-item a:hover - IDs: #main-nav --> 1 (Weight: 100) - Classes/Pseudos: .menu-item, :hover --> 2 (Weight: 20) - Elements: a --> 1 (Weight: 1) Total Specificity: (0, 1, 2, 1) = Beats any selector with 0 IDs regardless of class count!

The Box Model: content-box vs border-box

Every HTML element rendered on the page is an enclosed rectangular box consisting of four layers: Content, Padding, Border, and Margin.

+-----------------------------------------------------------+ | MARGIN | | +---------------------------------------------------+ | | | BORDER | | | | +-------------------------------------------+ | | | | | PADDING | | | | | | +-----------------------------------+ | | | | | | | | | | | | | | | CONTENT | | | | | | | | (width x height) | | | | | | | | | | | | | | | +-----------------------------------+ | | | | | +-------------------------------------------+ | | | +---------------------------------------------------+ | +-----------------------------------------------------------+
Figure 6.2: The Standard CSS Box Model
  • content-box (Default): The CSS width property sets ONLY the content width. Adding padding (20px) and border (2px) expands the element's actual rendered width on the screen: \[\text{Total Width} = \text{width} + \text{padding-left} + \text{padding-right} + \text{border-left} + \text{border-right}\]
  • border-box (Industry Standard): The CSS width property sets the TOTAL rendered width including padding and border: \[\text{Content Width} = \text{width} - \text{padding} - \text{border}\] 
/* Universal Box-Sizing Reset used in every modern production project */
*, *::before, *::after {
  box-sizing: border-box;
}

3. Flexbox versus CSS Grid

The golden rule for choosing modern CSS layout engines:

  • Flexbox: Designed for One-Dimensional layouts (distributing items along a single axis: either a row OR a column). Ideal for navbars, toolbars, vertical lists, card headers, and centering items.
  • CSS Grid: Designed for Two-Dimensional layouts (simultaneously managing rows AND columns). Ideal for full-page dashboards, photo galleries, magazine grids, and complex UI shells.
/* Centering any element perfectly in Flexbox */
.flex-center {
  display: flex;
  justify-content: center; /* Main axis (horizontal) */
  align-items: center;     /* Cross axis (vertical) */
}

/* Responsive Auto-Fitting Grid without media queries! */
.responsive-card-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(280px, 1fr));
  gap: 1.5rem;
}

4. Stacking Contexts and z-index Debugging

A common developer frustration is setting z-index: 999999 on an element, only for it to remain stubbornly hidden behind another element with z-index: 1.

This occurs because z-index only compares elements that participate in the same Stacking Context. An element in a lower stacking context can never appear in front of an element in a higher stacking context, no matter how high its internal z-index is!

What Creates a New Stacking Context?

  • The root document element (<html>).
  • An element with position: relative or absolute and a z-index other than auto.
  • An element with position: fixed or sticky.
  • An element with opacity less than 1.
  • An element with transform, filter, perspective, or clip-path not equal to none.
  • An element with isolation: isolate (the modern, clean way to force a new stacking context!).

5. DOM Event Propagation: Capturing, Target, and Bubbling

When an event (like a click) fires on a deeply nested element, it does not just execute on that element. It travels through three sequential phases:

| | 1. CAPTURING | | 3. BUBBLING PHASE | | PHASE | | Window | | ^ Window | | | | | v | | | | Document | | | Document | | | | | v | | | | | | | | | | | | v | | | | | | | | | | | | v | | | |
| | |
| | | | | v | | | |
Figure 6.3: The Three Phases of DOM Event Propagation
  1. Capturing Phase: The event descends from window down through the DOM tree toward the target node. (Listeners registered with addEventListener('click', fn, true) fire here).
  2. Target Phase: The event reaches the actual target element that was clicked (event.target).
  3. Bubbling Phase: The event bubbles back up from the target element through all its parent ancestor nodes up to window. (Standard listeners registered with addEventListener('click', fn, false) fire here).

Event Delegation Pattern

Instead of attaching 1,000 separate click event listeners to 1,000 list items (which burns memory and leaks when items are dynamically added), attach a single event listener to the parent container and utilize event bubbling: 

// Event Delegation
const taskList = document.getElementById("task-list");

taskList.addEventListener("click", (event) => {
  // Find closest button ancestor (in case user clicked an icon inside the button)
  const deleteBtn = event.target.closest(".btn-delete");
  if (!deleteBtn) return;

  const taskId = deleteBtn.dataset.taskId;
  console.log(`Deleting task ID: ${taskId}`);
  // deleteBtn.closest('.task-item').remove();
});

7. Browser Security: CORS and XSS

CORS (Cross-Origin Resource Sharing)

By default, browsers enforce the Same-Origin Policy (SOP): scripts running on Origin A (https://myapp.com:443) cannot read response data fetched from Origin B (https://api.other.com:443).

An origin is defined by the exact tuple: (Protocol, Domain, Port). If any one differs, it is cross-origin!

Client (https://frontend.com) Server (https://api.backend.com) | | | --- Preflight: OPTIONS /api/data --------------------------> | | Origin: https://frontend.com | | Access-Control-Request-Method: POST | | Access-Control-Request-Headers: Content-Type, Auth | | | | <--- Preflight OK: 204 No Content -------------------------- | | Access-Control-Allow-Origin: https://frontend.com | | Access-Control-Allow-Methods: GET, POST, OPTIONS | | Access-Control-Allow-Headers: Content-Type, Auth | | | | --- Actual Request: POST /api/data ------------------------> | | <--- 200 OK (JSON Payload) --------------------------------- |

XSS (Cross-Site Scripting) and Safe DOM Manipulation

XSS occurs when an application includes untrusted user input directly into HTML without sanitization, allowing attackers to execute arbitrary JavaScript in victim browsers. 

// VULNERABLE TO XSS:
// If comment.body is ''
// this executes the attacker's script and steals session cookies!
container.innerHTML = `<p>${comment.body}</p>`;

// SAFE: textContent encodes characters into harmless plain text entities
const p = document.createElement("p");
p.textContent = comment.body;
container.appendChild(p);

Interview Questions and Answers

20 high-frequency technical interview questions testing your mastery of DOM rendering, CSS mechanics, event architecture, browser storage, and client security.

Q1 What is the CSS Box Model, and what is the difference between `content-box` and `border-box`? Beginner
Spoken Interview Answer

"The CSS Box Model describes the rectangular boxes generated for elements, consisting of Content, Padding, Border, and Margin. With `content-box` (the default), setting `width: 200px` applies only to the content area; adding 20px padding and 2px border expands the total element width to 244px. With `border-box`, setting `width: 200px` guarantees that the total rendered width—including padding and border—remains exactly 200px. Because it makes responsive layouts predictable, we universally reset all elements to `box-sizing: border-box`."

Q2 How is CSS Specificity calculated? How does `!important` affect the cascade? Intermediate
Spoken Interview Answer

"Specificity is calculated as a four-part score: (Inline styles, IDs, Classes/Attributes/Pseudo-classes, Element tags). A selector with an ID always overrides any number of classes. When specificity scores are identical, the last declared rule in the stylesheet wins. Adding `!important` bypasses normal specificity completely; an `!important` rule can only be overridden by another `!important` rule with higher specificity. We avoid `!important` in production because it breaks the natural CSS cascade."

Q3 Explain the three phases of DOM Event Propagation. Intermediate
Spoken Interview Answer

"When an event occurs, it executes in three phases: 1. The Capturing Phase, where the event travels downward from `window` through ancestors to the target element. 2. The Target Phase, where the event triggers directly on the clicked element. 3. The Bubbling Phase, where the event bubbles back upward from the target element through all parent ancestors to `window`. Standard addEventListener listeners fire during the Bubbling phase unless the `capture: true` option is passed."

Q4 What is the difference between `event.stopPropagation()` and `event.stopImmediatePropagation()`? Advanced
Spoken Interview Answer

"`event.stopPropagation()` prevents the event from continuing to bubble up (or capture down) the DOM tree to ancestor elements, but other listeners attached to the *same element* will still execute. `event.stopImmediatePropagation()` stops bubbling up the tree AND immediately halts execution of any other remaining event listeners attached to the exact same element."

Q5 What is Event Delegation, and what are its performance and architectural advantages? Intermediate
Spoken Interview Answer

"Event delegation is a design pattern where you attach a single event listener to a common parent element rather than attaching individual listeners to multiple child elements. It leverages event bubbling: events on child elements bubble up to the parent, which inspects `event.target` (or `event.target.closest()`). It dramatically reduces memory usage and automatically works for dynamically added child elements without needing to attach new listeners."

Q6 What is a Stacking Context in CSS, and why might an element with `z-index: 9999` be hidden behind an element with `z-index: 1`? Advanced
Spoken Interview Answer

"A Stacking Context is a 3D conceptual layering of HTML elements along the Z-axis. `z-index` values only compete with sibling elements within the same stacking context. If Element A belongs to a parent whose stacking context has a lower z-index than Element B's parent, Element A can never appear above Element B, even if its internal z-index is set to 999999. Stacking contexts are created by properties like position relative with z-index, opacity < 1, transform, or `isolation: isolate`."

Q7 Compare Flexbox and CSS Grid. When would you choose one over the other? Intermediate
Spoken Interview Answer

"Flexbox is a one-dimensional layout system: it aligns items along a single axis (row or column). I choose Flexbox for UI components like navigation bars, button groups, centering cards, and vertical stacks. CSS Grid is a two-dimensional layout system: it arranges items simultaneously across both rows and columns. I choose Grid for page-level layouts, dashboard widgets, image galleries, and structured multi-column forms."

Q8 Compare `localStorage`, `sessionStorage`, and `cookies`. What are their primary differences? Beginner
Spoken Interview Answer

"`localStorage` stores up to 5MB of key-value data with no expiration; it persists across browser sessions and tabs. `sessionStorage` also stores 5MB but is scoped to a single tab session, clearing automatically when the tab closes. Cookies store only ~4KB and are automatically sent to the server in the HTTP `Cookie` header on every request. Cookies can be protected with `HttpOnly` to prevent XSS theft, whereas `localStorage` is always accessible to JavaScript."

Q9 What triggers a CORS preflight `OPTIONS` request? What defines a "Simple Request"? Intermediate
Spoken Interview Answer

"A preflight request is an HTTP `OPTIONS` request sent automatically by the browser to ask the server permission before sending the actual cross-origin request. A request is 'Simple' (skipping preflight) only if it uses GET, POST, or HEAD, uses safe headers (Accept, Accept-Language, Content-Language), and its Content-Type is application/x-www-form-urlencoded, multipart/form-data, or text/plain. As soon as you send JSON (`application/json`) or custom headers like `Authorization`, the browser triggers a preflight request."

Q10 What is Cross-Site Scripting (XSS)? What is the difference between Stored, Reflected, and DOM-based XSS? Advanced
Spoken Interview Answer

"XSS is an attack where malicious JavaScript is injected into a trusted web application. Stored XSS occurs when malicious input is saved permanently in the database (like a malicious comment) and served to all future visitors. Reflected XSS occurs when malicious script in a URL query parameter is reflected immediately in the server's HTML response. DOM-based XSS occurs entirely client-side when JavaScript reads from an untrusted source (like location.search) and inserts it directly into the DOM via innerHTML without sanitization."

Q11 Why should you avoid `innerHTML` when displaying user input, and what should you use instead? Beginner
Spoken Interview Answer

"`innerHTML` parses the supplied string as live HTML, allowing malicious script tags or image error handlers (``) to execute arbitrary code, leading to XSS vulnerabilities. Instead, you should use `element.textContent`, which treats all inputs strictly as raw text and automatically encodes dangerous HTML characters into harmless entities."

Q12 What is Content Security Policy (CSP), and how does it prevent XSS exploitation? Advanced
Spoken Interview Answer

"Content Security Policy is an HTTP response header (e.g., `Content-Security-Policy: default-src 'self'`) that allows site administrators to restrict the resources (scripts, images, stylesheets, iframes) the browser is permitted to load for a given page. It mitigates XSS by disallowing inline scripts (``), blocking `eval()`, and refusing to load external scripts from unauthorized third-party domains."

Q13 Scenario: How do you build an accessible Modal Dialog adhering to WAI-ARIA guidelines? Scenario
Spoken Interview Answer

"An accessible modal requires four criteria: 1. Semantic attributes: `role='dialog'`, `aria-modal='true'`, and `aria-labelledby` referencing the modal title. 2. Focus Management: Move keyboard focus inside the modal upon opening, and restore focus to the triggering button upon closing. 3. Focus Trapping: When the user presses Tab or Shift+Tab, keep focus cycling strictly within the modal's interactive elements. 4. Dismissal: Listen for the Escape key and outside backdrop clicks to close the modal."

Q14 What are CSS Custom Properties (Variables), and what advantages do they have over SASS/SCSS variables? Intermediate
Spoken Interview Answer

"CSS Custom Properties (`--my-var: #2563eb`) are native runtime CSS variables that participate in the DOM cascade and inheritance. SASS variables are evaluated at build time and cannot be altered dynamically in the browser. Because CSS variables exist at runtime, you can re-theme entire sites instantly using JavaScript (`document.documentElement.style.setProperty`), adapt them in media queries, and inherit them down DOM component trees."

Q15 What is Margin Collapsing in CSS, and when does it occur? Intermediate
Spoken Interview Answer

"Margin collapsing occurs when vertical (top and bottom) margins of adjacent block elements combine into a single margin whose size is equal to the largest individual margin, rather than adding together. It occurs between adjacent sibling blocks, between a parent and its first/last child when no border or padding separates them, and on empty blocks. Margin collapsing does NOT occur on horizontal margins, flex items, or grid items."

Q16 What are the three Core Web Vitals, and what does each measure? Advanced
Spoken Interview Answer

"Google's Core Web Vitals measure real-world user experience: 1. LCP (Largest Contentful Paint) measures loading performance: the time it takes for the largest image or text block in the viewport to render (target: < 2.5s). 2. INP (Interaction to Next Paint) measures responsiveness: latency between user interaction and next frame render (target: < 200ms). 3. CLS (Cumulative Layout Shift) measures visual stability: unexpected movement of visible page content during load (target: < 0.1)."

Q17 What is the difference between `display: none` and `visibility: hidden`? Beginner
Spoken Interview Answer

"`display: none` removes the element entirely from the browser Render Tree; it occupies zero physical space in the layout, triggering a full Reflow. `visibility: hidden` hides the element visually, but it remains in the Render Tree, preserving its original width, height, and layout space on the screen, triggering only a Repaint."

Q18 What is the purpose of the `aria-live` attribute? What is the difference between `polite` and `assertive`? Intermediate
Spoken Interview Answer

"`aria-live` announces dynamic content changes to screen reader users without requiring focus to move to that element (such as toast notifications or search results). With `aria-live='polite'`, the screen reader waits until the user has finished their current task before announcing the change. With `aria-live='assertive'`, the screen reader interrupts whatever it is currently reading to announce the message immediately, reserved for critical errors or alerts."

Q19 Scenario: You need to synchronize user theme preference (Light/Dark mode) across multiple open browser tabs in real time. How do you implement this? Scenario
Spoken Interview Answer

"I store the theme in `localStorage.setItem('theme', newTheme)` and listen for the native `window.addEventListener('storage', event => ...)` event. The storage event fires on all *other* open tabs belonging to the same origin when localStorage is modified. When the event fires with key === 'theme', the other tabs read `event.newValue` and immediately apply the corresponding `data-theme` attribute to `document.documentElement`."

Q20 What is CSS BEM methodology, and what problem does it solve in large codebases? Advanced
Spoken Interview Answer

"BEM stands for Block-Element-Modifier (`.card`, `.card__title`, `.card--highlighted`). It is a modular CSS naming convention designed to eliminate specificity wars and selector nesting bugs. By keeping every selector flat with a single class name (specificity 0, 0, 1, 0), it ensures high reusability, predictability, and prevents styles from accidentally leaking into child components."
