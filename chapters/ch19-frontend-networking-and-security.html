1. Fetch API vs Axios: The Definitive Architectural Comparison

Frontend developers must choose between the browser's native fetch() API and third-party HTTP clients like axios. Understanding their architectural differences is a classic interview question.

Feature Native Fetch API Axios
HTTP Error Rejections Does NOT reject on HTTP 4xx/5xx status codes! The Promise only rejects on true network failures. Requires manual if (!res.ok) throw Error(...) checks. Automatically rejects the promise for any HTTP status code outside the 2xx range (configurable via validateStatus).
JSON Parsing Manual 2-step process: const res = await fetch(...); const data = await res.json(); Automatic JSON transformation: response payload is directly available on res.data.
Interceptors No native support. Requires writing custom wrapper functions. First-class support for Request and Response interceptors (axios.interceptors).
Request Cancellation Supported via AbortController and signal. Supported via AbortController and signal (legacy CancelToken is deprecated).
Bundle Footprint 0 KB (Built directly into modern browsers and Node.js 18+). \(\approx\) 11–13 KB minified and gzipped.

2. Production Silent Token Refresh Interceptor

In token-based authentication architectures (JWT), short-lived Access Tokens expire after 10–15 minutes. When an access token expires while the user is actively using the application, the backend returns HTTP 401 Unauthorized.

Rather than forcing the user to log in again, the frontend must execute a Silent Refresh:

  1. Catch the HTTP 401 response in an interceptor.
  2. If multiple API calls fail simultaneously with 401, pause them and queue them up in memory.
  3. Execute a single call to POST /auth/refresh using the secure HttpOnly refresh token cookie.
  4. Upon success, update the stored access token, replay all queued requests with the new token, and resume normal execution.
  5. If the refresh token itself is expired or revoked, redirect the user to the login screen.

[ Component B: GET /orders  ] ----> [ 401 Expired ] ----+---> [ Request Queue ] (Paused)
[ Component C: GET /cart    ] ----> [ 401 Expired ] ---/             |

javascript (Production Axios Client) 
// src/api/apiClient.js
import axios from "axios";

let inMemoryAccessToken = null; // Store access token in memory, NEVER localStorage!
let isRefreshing = false;
let failedQueue = [];

export function setAccessToken(token) {
  inMemoryAccessToken = token;
}

export function getAccessToken() {
  return inMemoryAccessToken;
}

// Helper: Process pending queued requests once new token arrives
function processQueue(error, token = null) {
  failedQueue.forEach((prom) => {
    if (error) {
      prom.reject(error);
    } else {
      prom.resolve(token);
    }
  });
  failedQueue = [];
}

export const apiClient = axios.create({
  baseURL: "https://api.example.com",
  withCredentials: true, // Sends HttpOnly refresh cookies automatically
  headers: { "Content-Type": "application/json" }
});

// 1. Request Interceptor: Attach current access token
apiClient.interceptors.request.use(
  (config) => {
    if (inMemoryAccessToken && !config.headers.Authorization) {
      config.headers.Authorization = `Bearer ${inMemoryAccessToken}`;
    }
    return config;
  },
  (error) => Promise.reject(error)
);

// 2. Response Interceptor: Handle 401 and queue retries
apiClient.interceptors.response.use(
  (response) => response,
  async (error) => {
    const originalRequest = error.config;

    // Check if error is 401 Unauthorized and not already retried
    if (error.response?.status === 401 && !originalRequest._retry) {
      if (isRefreshing) {
        // If refresh is already in-flight, push this request into queue
        return new Promise((resolve, reject) => {
          failedQueue.push({ resolve, reject });
        })
          .then((token) => {
            originalRequest.headers.Authorization = `Bearer ${token}`;
            return apiClient(originalRequest);
          })
          .catch((err) => Promise.reject(err));
      }

      originalRequest._retry = true;
      isRefreshing = true;

      try {
        // Request new access token using HttpOnly cookie
        const { data } = await axios.post(
          "https://api.example.com/auth/refresh",
          {},
          { withCredentials: true }
        );

        const newAccessToken = data.accessToken;
        setAccessToken(newAccessToken);

        // Resume all queued promises with new token
        processQueue(null, newAccessToken);

        // Retry original request
        originalRequest.headers.Authorization = `Bearer ${newAccessToken}`;
        return apiClient(originalRequest);
      } catch (refreshErr) {
        processQueue(refreshErr, null);
        setAccessToken(null);
        // Token refresh failed: user session is dead, redirect to login
        window.location.href = "/login?expired=true";
        return Promise.reject(refreshErr);
      } finally {
        isRefreshing = false;
      }
    }

    return Promise.reject(error);
  }
);

3. Request Cancellation with AbortController

Uncancelled network requests cause two major problems in React:

  1. Memory Leaks / Warning Noise: Fetching data for a component that unmounts before the network request resolves.
  2. Asynchronous Race Conditions: A user rapidly clicks between tabs or types search queries; an earlier slow query resolves after a later fast query, overwriting the UI with outdated results.
javascript 
import { useState, useEffect } from "react";
import { apiClient } from "../api/apiClient";

export function UserSearch() {
  const [query, setQuery] = useState("");
  const [results, setResults] = useState([]);
  const [isLoading, setIsLoading] = useState(false);

  useEffect(() => {
    if (!query.trim()) {
      setResults([]);
      return;
    }

    // 1. Create an AbortController instance for this specific search run
    const controller = new AbortController();

    async function searchUsers() {
      setIsLoading(true);
      try {
        const response = await apiClient.get(`/users/search?q=${encodeURIComponent(query)}`, {
          signal: controller.signal // Pass signal to Axios or fetch()
        });
        setResults(response.data);
      } catch (err) {
        // Axios wraps AbortErrors inside axios.isCancel(err)
        if (err.name === "CanceledError" || err.name === "AbortError") {
          console.log("[Search] Request cancelled due to new input.");
        } else {
          console.error("[Search] Network error:", err.message);
        }
      } finally {
        setIsLoading(false);
      }
    }

    searchUsers();

    // 2. Cleanup: Cancel pending request if query changes or component unmounts!
    return () => {
      controller.abort();
    };
  }, [query]);

  return (
    <div>
      <input
        type="text"
        placeholder="Search users..."
        value={query}
        onChange={(e) => setQuery(e.target.value)}
      />
      {isLoading && <span>Searching...</span>}
      <ul>
        {results.map((u) => (
          <li key={u.id}>{u.name}</li>
        ))}
      </ul>
    </div>
  );
}

4. Cross-Site Scripting (XSS) in React Applications

Cross-Site Scripting (XSS) occurs when an attacker tricks a web application into executing malicious JavaScript code within the context of an unsuspecting user's browser session. If executed, the attacker can steal credentials, hijack sessions, and impersonate the user.

4.1 React's Built-in Protection: Automatic String Escaping

By default, React escapes all string values embedded inside JSX before rendering them to the DOM:

javascript 
const maliciousInput = "<img src=x onerror=alert('XSS') />";

// SAFE: React renders this as plain literal text in a DOM TextNode, NOT executable HTML:
return <div>{maliciousInput}</div>;
// DOM output: &lt;img src=x onerror=alert('XSS') /&gt;

4.2 Where React Remains Vulnerable to XSS

Vulnerable Pattern Why It Is Dangerous Remediation Strategy
dangerouslySetInnerHTML Directly inserts unescaped HTML strings into the real DOM. If content originates from user input or rich-text markdown, script tags or malicious <img onerror> payloads execute immediately. Always sanitize input using DOMPurify before passing to __html: DOMPurify.sanitize(dirtyHtml).
User-Supplied <a href> Links If a user profile allows setting a website URL and the attacker provides javascript:alert(document.cookie), clicking the link executes JavaScript! React does not escape URL protocols! Validate that URL protocols strictly start with https:// or http:// before rendering. Reject javascript: and data: URIs.
Reflected Props in SSR Embedding server data directly in the HTML string without escaping: <script>window.__PRELOADED_STATE__ = ${JSON.stringify(data)}</script> allows closing the tag with </script>. Serialize JSON safely using serialize-javascript which replaces < with Unicode escapes (\\u003C).

Q16 What is the purpose of the rel='noopener noreferrer' attribute on external links? Beginner
Spoken Interview Answer

"When opening external links with `target='_blank'`, the target page gets access to the opening page's `window.opener` object. A malicious site can execute `window.opener.location = 'phishing.com'`, redirecting the original tab without the user noticing ('Tabnabbing'). `noopener` instructs the browser to set `window.opener` to null, isolating the new tab. `noreferrer` also suppresses the HTTP `Referer` header."

Q17 What is an Open Redirect vulnerability, and how can frontend applications mitigate it? Intermediate
Spoken Interview Answer

"An open redirect occurs when an application accepts an unvalidated user-controlled URL parameter (e.g. `/login?returnTo=https://evil.com`) and redirects the user after authentication. Attackers use this to craft authentic-looking login links that bounce users to phishing sites. Mitigate it by validating that `returnTo` URLs strictly start with a single forward slash `/` (relative path) and never start with `//` (protocol-relative) or external domains."

Q18 Scenario: How would you detect when a client loses internet connectivity and display an offline banner in React? Scenario
Spoken Interview Answer

"I would create a custom hook `useOnlineStatus()` that reads `navigator.onLine` and subscribes to window `online` and `offline` event listeners. Inside a `useEffect`, update a state boolean when these events fire and remove listeners in cleanup. The root component renders an accessible notification banner when `isOnline` is false, pausing automated network polling until the connection is restored."
