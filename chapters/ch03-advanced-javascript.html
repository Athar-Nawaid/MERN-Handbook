1. Execution Contexts and Lexical Environments

Whenever JavaScript executes code, it does so inside an Execution Context. An Execution Context is an abstract conceptual environment containing everything necessary to evaluate the current script or function.

The Three Types of Execution Context

  1. Global Execution Context (GEC): The base context created when the script first loads. It creates the global object (window in browsers, global in Node.js) and sets this to the global object.
  2. Function Execution Context (FEC): Created dynamically every time a function is invoked. Each function call gets its own brand-new execution context.
  3. Eval Execution Context: Code executed inside the eval() string function (strictly discouraged in production).
+--------------------------------------------------------------------------+ | EXECUTION CONTEXT STRUCTURE | +--------------------------------------------------------------------------+ | 1. LexicalEnvironment | | - EnvironmentRecord: Stores let, const, function declarations | | - OuterEnvRef: Pointer to parent lexical scope (Scope Chain) | | | | 2. VariableEnvironment | | - EnvironmentRecord: Stores legacy 'var' bindings | | | | 3. ThisBinding: Evaluated at runtime based on invocation pattern | +--------------------------------------------------------------------------+
Figure 3.1: Internal Components of a V8 Execution Context

The Two Phases of Every Execution Context

  • Phase 1: Creation Phase (Compilation): The engine allocates memory for variables and functions. var declarations are initialized to undefined; let/const are declared but remain uninitialized (TDZ); function declarations are placed into memory in their entirety.
  • Phase 2: Execution Phase: Code is evaluated line by line. Variables are assigned their actual runtime values, and functions are executed.

2. The `this` Keyword: The 4 Binding Rules

In JavaScript, this is not bound lexically based on where a function was written (except for arrow functions). Instead, this is determined dynamically at the call-site when the function is invoked.

Precedence Binding Rule Invocation Syntax What `this` Points To
1 (Highest) new Binding new MyFunc() Points to the newly instantiated object in the heap.
2 Explicit Binding fn.call(ctx), fn.apply(ctx), fn.bind(ctx) Points explicitly to the provided ctx object.
3 Implicit Binding obj.method() Points to the context object before the dot (obj).
4 (Lowest) Default Binding Standalone call: fn() undefined in strict mode ("use strict"); global object in non-strict mode.

Rule Exceptions: Arrow Functions

Arrow functions do not have their own this. They resolve this lexically, searching up the scope chain to the enclosing execution context where they were defined. 

const team = {
  name: "Platform Engineering",
  members: ["Alice", "Bob"],
  
  // Buggy approach with regular function:
  printMembersRegular() {
    this.members.forEach(function(member) {
      // In a regular function callback, 'this' defaults to undefined or global window!
      console.log(`${member} works in ${this.name}`); // TypeError or "undefined"
    });
  },

  // Fixed approach with Arrow Function (inherits 'this' from printMembersArrow):
  printMembersArrow() {
    this.members.forEach(member => {
      console.log(`${member} works in ${this.name}`); // Works! "Alice works in Platform Engineering"
    });
  }
};

3. Call, Apply, and Bind

When you need to borrow a method or explicitly specify what this points to, JavaScript provides three standard prototype methods on Function.prototype.

  • call(thisArg, arg1, arg2, ...): Invokes the function immediately, passing arguments comma-separated.
  • apply(thisArg, [arg1, arg2, ...]): Invokes the function immediately, passing arguments as an array.
  • bind(thisArg, arg1, arg2, ...): Does not invoke immediately. Returns a new bound function with this permanently locked to thisArg.
Interview Polyfill: Implement `Function.prototype.myBind` Senior Level

Write an exact vanilla JavaScript polyfill for Function.prototype.bind using closures and method borrowing.

Function.prototype.myBind = function(context, ...boundArgs) {
  if (typeof this !== "function") {
    throw new TypeError("Function.prototype.bind - what is trying to be bound is not callable");
  }

  const originalFunction = this;

  return function(...invokedArgs) {
    // Merge bound arguments from bind() with runtime arguments from invocation
    return originalFunction.apply(context, [...boundArgs, ...invokedArgs]);
  };
};

// Verification:
function greet(greeting, punctuation) {
  return `${greeting}, ${this.name}${punctuation}`;
}

const user = { name: "Sarah" };
const greetSarah = greet.myBind(user, "Welcome");
console.log(greetSarah("!")); // Output: "Welcome, Sarah!"

4. Prototypes and Prototype Inheritance

Unlike Java, C++, or C# which use classical class-based inheritance, JavaScript uses Prototypal Inheritance. Objects inherit properties directly from other objects through an internal link called [[Prototype]] (accessible in code via __proto__ or Object.getPrototypeOf()).

+---------------------+ [[Prototype]] +-----------------------+ | Instance: dog | -------------------------> | Animal.prototype | | name: 'Rex' | | bark: function() | +---------------------+ +-----------------------+ | [[Prototype]] v +-----------------------+ | Object.prototype | | toString, hasOwn | +-----------------------+ | [[Prototype]] v null
Figure 3.2: The Prototype Delegation Chain terminating at null

How Property Lookup Works

When accessing dog.bark():

  1. The engine checks if dog owns the property directly (dog.hasOwnProperty('bark')). If yes, it executes it.
  2. If not found, it traverses up the [[Prototype]] link to Animal.prototype.
  3. If still not found, it traverses to Object.prototype.
  4. If it reaches null without finding the property, it returns undefined (or throws a TypeError if invoked).
// Prototypal Inheritance using Object.create()
const animal = {
  eats: true,
  walk() {
    return `${this.name} walks.`;
  }
};

const rabbit = Object.create(animal); // rabbit.[[Prototype]] = animal
rabbit.name = "White Rabbit";

console.log(rabbit.eats);   // true (Inherited from animal)
console.log(rabbit.walk()); // "White Rabbit walks." ('this' points to rabbit!)
console.log(Object.getPrototypeOf(rabbit) === animal); // true

5. Iterators and Generator Functions

An Iterator is an object that implements the Iterator Protocol: an object with a next() method that returns an object containing { value: any, done: boolean }.

A Generator Function (declared with function*) is a special function that can pause execution (using yield) and resume later, yielding values lazily on demand. 

// Infinite ID Generator (Memory efficient - does not store millions of IDs)
function* idGenerator(prefix = "id") {
  let id = 1;
  while (true) {
    yield `${prefix}_${id++}`;
  }
}

const gen = idGenerator("user");
console.log(gen.next()); // { value: 'user_1', done: false }
console.log(gen.next()); // { value: 'user_2', done: false }
console.log(gen.next()); // { value: 'user_3', done: false }

6. Debouncing versus Throttling

Both debouncing and throttling limit how frequently a function can execute, but they solve different UI interaction problems:

Pattern Core Mechanics Primary Use Cases
Debounce Delays execution until the user has stopped triggering calls for \(N\) milliseconds. Every new event resets the timer. Search input auto-complete, window resize recalculations, form autosave.
Throttle Guarantees execution at a regular fixed maximum frequency (at most once every \(N\) milliseconds), regardless of how many events fire. Infinite scroll pagination on scroll, drag-and-drop mouse movements, game loop actions. 
// Production-Grade Throttle Implementation
function throttle(fn, limit = 200) {
  let inThrottle = false;

  return function(...args) {
    if (!inThrottle) {
      fn.apply(this, args);
      inThrottle = true;
      setTimeout(() => {
        inThrottle = false;
      }, limit);
    }
  };
}

// Window scroll throttled to execute at most once every 200ms
window.addEventListener("scroll", throttle(() => {
  console.log("Checking infinite scroll position...");
}, 200));

Interview Questions and Answers

20 senior-level JavaScript interview questions covering `this` binding, prototypes, inheritance, execution context, memory management, and function engineering.

Q1 What are the 4 rules governing `this` binding in JavaScript, in order of precedence? Intermediate
Spoken Interview Answer

"In order of highest to lowest precedence: 1. `new` binding (calling a function with `new` binds `this` to the newly allocated instance), 2. Explicit binding (using call, apply, or bind explicitly assigns `this`), 3. Implicit binding (calling a method on an object context like `obj.method()` binds `this` to `obj`), and 4. Default binding (standalone invocation `fn()` binds `this` to undefined in strict mode, or the global object in non-strict mode). Arrow functions are the exception: they do not have their own `this` and inherit it lexically."

Q2 What is the difference between `__proto__` and `prototype`? Advanced
Spoken Interview Answer

"`prototype` is a property found exclusively on constructor functions and classes. It defines the blueprint of methods and properties that will be assigned as the `[[Prototype]]` to any instances created via the `new` keyword. `__proto__` (or `[[Prototype]]`) is an internal property present on *every* object instance that points directly to the prototype object it inherits from." 

function Person(name) { this.name = name; }
Person.prototype.sayHi = function() { return "Hi"; };

const alice = new Person("Alice");
console.log(alice.__proto__ === Person.prototype); // true
console.log(Person.__proto__ === Function.prototype); // true
Q3 What is the difference between `call()`, `apply()`, and `bind()`? Intermediate
Spoken Interview Answer

"`call` and `apply` both execute the function immediately with a specified `this` context; `call` accepts arguments individually separated by commas, while `apply` accepts them as an array. `bind` does not execute the function immediately; it returns a brand-new bound function with its `this` context and initial arguments permanently locked."

Q4 Can you override a function's `this` context if it has already been bound using `.bind()`? Advanced
Spoken Interview Answer

"No. Once a function is hard-bound with `.bind()`, subsequent calls to `.call()`, `.apply()`, or another `.bind()` cannot override the original `this` context. The only exception that can override a bound function's `this` is invoking it as a constructor with the `new` operator, which binds `this` to the newly created instance."

Q5 What is the difference between Debouncing and Throttling? Give an example for each. Intermediate
Spoken Interview Answer

"Debounce delays execution until a burst of rapid events stops for a specified quiet period—for example, waiting for a user to pause typing before triggering a search API query. Throttle enforces a maximum execution frequency over time—for example, firing a scroll handler at most once every 100ms regardless of how many hundreds of scroll events the mouse generates."

Q6 What happens when you invoke a constructor with the `new` keyword? Trace the 4 steps. Advanced
Spoken Interview Answer

"Four distinct steps occur: 1. A brand-new empty JavaScript object is allocated in the heap: `{}`. 2. The internal `[[Prototype]]` (`__proto__`) of this new object is linked to the constructor's `prototype` object. 3. The constructor function is executed with `this` explicitly bound to the new object. 4. If the constructor returns its own non-primitive object, that object is returned; otherwise, the newly created instance is returned automatically."

Q7 What is a Pure Function, and what are its two core rules? Intermediate
Spoken Interview Answer

"A pure function satisfies two deterministic properties: 1. Given the identical arguments, it will always return the exact same output. 2. It has zero observable side effects—it does not mutate external variables, alter arguments, read from non-deterministic sources like Math.random() or Date.now(), or execute network/disk I/O."

Q8 What is the difference between Function Composition using `pipe` vs `compose`? Advanced
Spoken Interview Answer

"Both take multiple functions and return a new function where the output of each function becomes the input of the next. The difference is evaluation direction: `compose` executes functions from right to left (standard in mathematical notation: f(g(x))), while `pipe` executes from left to right, matching human reading order." 

const pipe = (...fns) => x => fns.reduce((val, fn) => fn(val), x);
const compose = (...fns) => x => fns.reduceRight((val, fn) => fn(val), x);
Q9 What is the difference between `Array.prototype.map()` and `Array.prototype.forEach()`? Beginner
Spoken Interview Answer

"`forEach` is an iteration method that executes a callback on each element for side effects and returns `undefined`. `map` transforms each element and returns a brand-new array of equal length containing the transformed values, leaving the original array untouched."

Q10 How does `Array.prototype.reduce()` work? What happens if you omit the initial value? Intermediate
Spoken Interview Answer

"`reduce` iterates over an array and reduces it down to a single accumulated value (which can be a number, object, or array). If an initial value is supplied, the accumulator starts with that value and iteration begins at index 0. If omitted, the accumulator starts with the element at index 0, and iteration begins at index 1. Omission on an empty array throws a runtime TypeError."

Q11 Explain what a Generator Function is and how the `yield` keyword operates. Advanced
Spoken Interview Answer

"A generator function (function*) returns a Generator object that adheres to both the Iterable and Iterator protocols. When called, the body does not execute immediately. Calling .next() runs the code until it encounters the `yield` keyword, which pauses the function's execution frame and returns the yielded value. Calling .next() again resumes execution right where it was paused with all local state intact."

Q12 What is a WeakMap and WeakSet? How do they differ from Map and Set regarding garbage collection? Advanced
Spoken Interview Answer

"In a standard Map or Set, keys/values are held with strong references; as long as the Map exists, those objects cannot be garbage-collected, creating potential memory leaks. In WeakMap and WeakSet, keys MUST be objects and are held with *weak references*. If there are no other references to a key object in the application, the garbage collector will reclaim it even if it is still registered in the WeakMap. Because of this, WeakMaps are not iterable and have no .size property."

Q13 Scenario: You have an object with circular references (`obj.self = obj`). Why does `JSON.stringify(obj)` throw an error, and how do you handle it? Scenario
Spoken Interview Answer

"`JSON.stringify()` recursively traverses object keys. When it encounters a circular reference pointing back to an ancestor node, it enters an infinite recursion loop and throws a `TypeError: Converting circular structure to JSON`. To clone or serialize it, use the modern native `structuredClone()` API, or pass a custom replacer function utilizing a WeakSet to track already-visited object references."

Q14 What are ES6 Classes under the hood? Are they actual classes like in C++ or syntax sugar? Intermediate
Spoken Interview Answer

"ES6 Classes are predominantly syntactic sugar layered on top of JavaScript's existing prototype-based inheritance model. Under the hood, declaring a class creates a constructor function, and any methods declared inside the class body are attached directly to the constructor's `.prototype` object. However, classes add strict semantics: they cannot be called without `new`, class methods are non-enumerable by default, and class bodies always execute in strict mode."

Q15 Explain the difference between `Object.create(proto)` and `new Constructor()`. Intermediate
Spoken Interview Answer

"`Object.create(proto)` creates a new object whose prototype is explicitly set to `proto` without executing any constructor function. `new Constructor()` executes the constructor function's code with `this` bound to the new object, and links its prototype to `Constructor.prototype`."

Q16 What is Tail Call Optimization (TCO)? Does JavaScript support it? Advanced
Spoken Interview Answer

"Tail Call Optimization is a compiler feature where calling a function as the final return expression of another function reuses the existing stack frame instead of allocating a new one, preventing stack overflow on deep recursion. While specified in ES6 for strict mode, V8 (Node/Chrome) and SpiderMonkey (Firefox) chose not to implement it because it breaks call-stack tracing for error debugging; only WebKit (Safari) implements it."

Q17 What is the difference between `try...catch...finally`? When does `finally` execute? Beginner
Spoken Interview Answer

"`try` wraps code that might throw an error; `catch` intercepts and handles the error if one is thrown; and `finally` is a guaranteed cleanup block that executes unconditionally, whether an error occurred or not, and even if the try or catch block executes an explicit `return` statement."

Q18 How does the V8 engine optimize property access on objects? What are Hidden Classes and Shapes? Advanced
Spoken Interview Answer

"Since JavaScript is dynamic, dictionary lookups for properties would be slow. V8 generates internal 'Hidden Classes' (Shapes) at runtime. Objects initialized with the identical properties in the exact same order share the same hidden class and memory offsets. If you dynamically add properties or change initialization order, V8 transitions to a new shape, deoptimizing inline caches."

Q19 Scenario: What does this code print, and why? Scenario 
const obj = {
  count: 10,
  regular() {
    return this.count;
  },
  arrow: () => {
    return this.count;
  }
};

const extractRegular = obj.regular;
console.log(obj.regular());
console.log(extractRegular());
console.log(obj.arrow());
Spoken Interview Answer

"1. `obj.regular()` logs 10 because it is invoked via implicit binding with `obj` as the context. 2. `extractRegular()` logs `undefined` (or throws in strict mode) because it was assigned to a standalone variable, triggering default binding to the global context where count does not exist. 3. `obj.arrow()` logs `undefined` because arrow functions inherit `this` from the enclosing lexical scope (the global file/module scope where obj was declared), NOT from the object literal body!"

Q20 Scenario: You need to create an immutable data pipeline that trims, lowercases, and replaces spaces with dashes for URL slugs. How do you write it cleanly using function composition? Scenario
Spoken Interview Answer

"I define individual pure unary functions for each transformation step and combine them using a `pipe` higher-order function, ensuring data immutability and readability." 

const trim = str => str.trim();
const toLower = str => str.toLowerCase();
const replaceSpaces = str => str.replace(/\s+/g, '-');

const pipe = (...fns) => initialVal => fns.reduce((acc, fn) => fn(acc), initialVal);

const slugify = pipe(trim, toLower, replaceSpaces);

console.log(slugify("   Advanced JavaScript Architecture & Internals   "));
// Output: "advanced-javascript-architecture-&-internals"
