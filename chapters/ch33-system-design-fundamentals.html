2. Back-of-the-Envelope Estimation & Latency Numbers

To make sound architectural decisions, engineers must understand hardware orders of magnitude. Jeff Dean (Chief Scientist at Google) popularized the "Latency Numbers Every Programmer Should Know":

Operation Latency (Real Time) Human Scaled (1 ns = 1 sec)
L1 CPU Cache Reference ~0.5 – 1.0 ns 1 second
L2 CPU Cache Reference ~3.0 – 4.0 ns 3 – 4 seconds
Main Memory (RAM) Reference ~100 ns 1.6 minutes
Read 1 MB sequentially from RAM ~3 – 4 µs 1 hour
Read 1 MB sequentially from NVMe SSD ~200 µs 2.3 days
Read 1 MB sequentially from Spinning Disk (HDD) ~10,000 – 20,000 µs (10–20 ms) 4 months
Intra-Datacenter Network Round-Trip ~500 µs (0.5 ms) 5.7 days
Transatlantic Network Ping (US to Europe) ~150,000 µs (150 ms) 4.7 years

Powers of Two Byte Math

Quick mental conversions prevent embarrassing calculation stalls in interviews:

  • \(2^{10} \approx 1,000\) bytes = 1 KB (Kilobyte)
  • \(2^{20} \approx 1,000,000\) bytes = 1 MB (Megabyte)
  • \(2^{30} \approx 1,000,000,000\) bytes = 1 GB (Gigabyte)
  • \(2^{40} \approx 1,000,000,000,000\) bytes = 1 TB (Terabyte)
  • \(2^{50} \approx 1,000,000,000,000,000\) bytes = 1 PB (Petabyte)
  • Seconds in a day: \(24 \times 60 \times 60 = 86,400\) (Round to \(10^5\) or \(86,000\) in mental math).

Step-by-Step Calculation Walkthrough

Scenario: Design a status feed application with 100 Million Daily Active Users (DAU). On average, each user reads 20 feed posts per day and publishes 2 new posts per day. Each post payload is 500 bytes.

  1. Read Throughput (QPS): \[ \text{Daily Reads} = 100\text{M users} \times 20 = 2\text{ Billion reads/day} \] \[ \text{Read QPS} = \frac{2,000,000,000}{86,400 \text{ sec}} \approx 23,000 \text{ QPS} \] \[ \text{Peak Read QPS} (\times 2) \approx 46,000 \text{ QPS} \]
  2. Write Throughput (QPS): \[ \text{Daily Writes} = 100\text{M users} \times 2 = 200\text{ Million writes/day} \] \[ \text{Write QPS} = \frac{200,000,000}{86,400 \text{ sec}} \approx 2,300 \text{ QPS} \]
  3. 5-Year Storage Requirement: \[ \text{Daily Data} = 200\text{M posts} \times 500 \text{ bytes} = 100\text{ GB / day} \] \[ \text{Annual Data} = 100\text{ GB} \times 365 \approx 36.5\text{ TB / year} \] \[ \text{5-Year Storage} = 36.5\text{ TB} \times 5 \approx 182.5\text{ TB} \]

3. Vertical vs. Horizontal Scaling Economics

Scaling Dimension Vertical Scaling (Scale-Up) Horizontal Scaling (Scale-Out)
Mechanism Add more CPU cores, RAM, and faster NVMe drives to a single server instance (e.g., upgrading from AWS t3.large to u-24tb1.112xlarge). Add more independent commodity instances behind a load balancer (e.g., running 20 c6i.xlarge instances in an Auto Scaling Group).
Hardware Limits & Cost Hard physical hardware limits (motherboard sockets, memory bus). High-end enterprise servers exhibit steep non-linear cost curves. Virtually unlimited horizontal elasticity. Linear cost model using cheap, interchangeable commodity cloud VMs.
Software Complexity Extremely simple: zero distributed system coordination, zero network serialization latency, standard ACID transactions. Complex: requires load balancers, stateless application design, distributed caching, data partitioning, and eventual consistency.
Availability & SPOF Single Point of Failure: if the physical motherboard or hypervisor crashes, the entire system is down. Fault-tolerant: individual nodes can fail or be recycled without disrupting overall system availability.

4. Load Balancing: Layer 4 vs. Layer 7

A Load Balancer (LB) distributes incoming traffic across a pool of backend servers to prevent overload and ensure high availability.

Feature Layer 4 Load Balancer (Transport Layer) Layer 7 Load Balancer (Application Layer)
OSI Layer & Inspection Operates at Layer 4 (TCP/UDP). Inspects only IP addresses and TCP port numbers. Does not parse HTTP payloads. Operates at Layer 7 (Application). Decrypts TLS and parses HTTP headers, cookies, query parameters, and JSON bodies.
Performance & Overhead ⚡ Ultra-fast; minimal CPU overhead. Simply routes raw TCP packets via NAT (Network Address Translation). ⏳ Higher CPU overhead due to TLS termination and deep HTTP packet inspection.
Routing Capabilities Blind forwarding based only on IP/Port. Cannot route based on URI path or headers. Intelligent routing: routes /api/v1/auth to auth cluster, /images/* to CDN/S3, or checks cookies for session sticky routing.
Examples AWS Network Load Balancer (NLB), HAProxy (TCP mode), IPVS, LVS. AWS Application Load Balancer (ALB), Nginx, Envoy, Cloudflare.

Load Balancing Algorithms

  • Round Robin: Distributes requests sequentially across servers. Best when all instances have identical hardware and requests have uniform processing times.
  • Weighted Round Robin: Assigns higher request quotas to servers with more CPU/RAM capacity.
  • Least Connections: Directs traffic to the server with the fewest active concurrent connections. Ideal for long-lived WebSocket connections or varied transaction durations.
  • IP Hash / Sticky Sessions: Hashes the client's IP address to route them deterministically to the same server. Essential when legacy applications store in-memory state, though it impairs autoscaling elasticity.
  • Consistent Hashing: Maps both servers and resource keys to an abstract hash ring. When nodes are added or removed, only \(1/N\) of keys need to be remapped, minimizing cache churn.

5. Content Delivery Networks (CDNs) & Edge Caching

A Content Delivery Network (CDN) is a geographically distributed network of proxy servers (Points of Presence / PoPs) positioned close to end users to deliver static and cacheable dynamic web assets with minimal latency.

6. High Availability SLA Engineering ("The Nines")

Availability is mathematically calculated as: \[ \text{Availability} = \frac{\text{Uptime}}{\text{Uptime} + \text{Downtime}} \]

Availability SLA Downtime per Year Downtime per Month Typical Architecture Requirements
99% ("Two Nines") 3 days, 15 hours 7 hours, 18 mins Single cloud VM; manual backups; regular maintenance windows permitted.
99.9% ("Three Nines") 8 hours, 45 mins 43 minutes Load-balanced multi-instance tier; automated database failover within a single cloud region.
99.99% ("Four Nines") 52 minutes, 36 secs 4.3 minutes Multi-Availability Zone (Multi-AZ) active-active architecture; automated health checks; zero-downtime rolling deploys.
99.999% ("Five Nines") 5 minutes, 15 secs 26 seconds Multi-region active-active deployments; automated traffic failover via Anycast/DNS; telecom and financial grade resilience.

7. Practical Exercises

Exercise 1: Back-of-the-Envelope Capacity Estimation

Scenario: You are designing a URL Shortener (like TinyURL). It handles 500 Million new URLs created per month. Read to write ratio is 100:1. URLs must be stored for 10 years. Calculate: 1) Write QPS, 2) Read QPS, 3) 10-year storage capacity assuming each record takes 500 bytes.

View Complete Solution
Calculation Solution 
1. Write QPS:
   500M URLs / month = 500M / (30 days * 86,400s) = 500,000,000 / 2,592,000s
   Write QPS ~ 193 writes/sec (Round to ~200 QPS)

2. Read QPS (100:1 ratio):
   Read QPS = 200 * 100 = 20,000 reads/sec
   Peak Read QPS (~2x) = 40,000 reads/sec

3. 10-Year Storage Requirement:
   Total Records = 500M/month * 12 months * 10 years = 60 Billion URLs
   Storage = 60 Billion * 500 bytes = 30,000 Billion bytes
   30,000,000,000,000 bytes / (10^12) = 30 Terabytes (TB)

Conclusion:
30 TB over 10 years fits comfortably within modern relational or NoSQL database clusters with modest disk provisioning.

Exercise 2: Nginx Reverse Proxy with Rate Limiting and Load Balancing

Scenario: Configure an Nginx reverse proxy that distributes traffic across two Node.js upstream servers (app1:3000 and app2:3000) using least-connections balancing, terminates TLS, and enforces an IP rate limit of 10 req/sec.

View Complete Solution
Nginx Configuration 
http {
  # 1. Rate limiting zone: 10MB memory zone storing IPs, max 10 requests/sec
  limit_req_zone $binary_remote_addr zone=api_limit:10m rate=10r/s;

  upstream node_cluster {
    least_conn; # Least connections balancing algorithm
    server app1:3000 max_fails=3 fail_timeout=10s;
    server app2:3000 max_fails=3 fail_timeout=10s;
  }

  server {
    listen 443 ssl http2;
    server_name api.myapp.com;

    ssl_certificate /etc/ssl/certs/fullchain.pem;
    ssl_certificate_key /etc/ssl/private/privkey.pem;

    location / {
      # Apply rate limit with burst buffer of 20 requests
      limit_req zone=api_limit burst=20 nodelay;

      proxy_pass http://node_cluster;
      proxy_http_version 1.1;
      proxy_set_header Upgrade $http_upgrade;
      proxy_set_header Connection 'upgrade';
      proxy_set_header Host $host;
      proxy_set_header X-Real-IP $remote_addr;
      proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
      proxy_set_header X-Forwarded-Proto $scheme;
    }
  }
}

8. Chapter-Specific Interview Questions & Answers

20 high-frequency interview questions covering system design frameworks, capacity calculations, load balancers, caching economics, and high availability SLAs.

Q01 What are the 4 core steps to navigate a System Design interview? Beginner
Spoken Interview Answer

"The four steps are: 1) Understand the problem and clarify requirements (functional, non-functional like DAU, latency, availability); 2) High-level design and capacity calculations (estimating QPS, storage, and drawing the initial end-to-end architecture); 3) Deep dive into core bottlenecks (data modeling, sharding, caching strategies, and concurrency); and 4) Fault tolerance and wrap-up (addressing single points of failure, failovers, and monitoring)."

Q02 What is the difference between Vertical Scaling and Horizontal Scaling? Beginner
Spoken Interview Answer

"Vertical scaling (Scale-Up) means adding more hardware resources—CPU, RAM, or faster SSDs—to a single server instance. Horizontal scaling (Scale-Out) means adding more commodity server instances behind a load balancer. While vertical scaling is simpler because it avoids distributed coordination, horizontal scaling provides true elastic scalability and fault tolerance."

Q03 What is the difference between a Reverse Proxy and a Forward Proxy? Beginner
Spoken Interview Answer

"A Forward Proxy acts on behalf of clients to access the external internet, often used in corporate firewalls to filter employee web traffic and hide client IPs. A Reverse Proxy acts on behalf of backend servers to receive incoming public internet requests, performing SSL termination, load balancing, compression, and protecting internal application instances from direct public exposure."

Q04 What is a Content Delivery Network (CDN) and why is it used? Beginner
Spoken Interview Answer

"A CDN is a globally distributed network of proxy edge servers that cache static assets (JavaScript, CSS, images, video) close to end users geographically. It minimizes round-trip network latency by terminating TCP and TLS connections near the client, decreases origin backend server load, and absorbs DDoS traffic at the edge."

Q05 What does 'Three Nines' vs 'Four Nines' availability mean in practice? Beginner
Spoken Interview Answer

"Three Nines (99.9% uptime) permits approximately 8 hours and 45 minutes of total downtime per year. Four Nines (99.99% uptime) permits only about 52 minutes of downtime per year. Moving from three to four nines requires eliminating single points of failure, multi-AZ active-active failover, and automated zero-downtime deployment pipelines."

Q06 What is the difference between Layer 4 and Layer 7 Load Balancing? Intermediate
Spoken Interview Answer

"Layer 4 load balancing operates at the transport layer (TCP/UDP), routing raw network packets based solely on IP and port without decrypting or inspecting payload data; it is ultra-fast with minimal CPU overhead. Layer 7 balancing operates at the application layer (HTTP/HTTPS), parsing headers, cookies, and URIs to perform intelligent path-based routing and SSL termination, but incurs higher computational overhead."

Q07 What is Consistent Hashing and why is it preferred over simple modulo hashing? Intermediate
Spoken Interview Answer

"With simple modulo hashing (`hash(key) % N`), adding or removing a single node changes the denominator, causing virtually 100% of keys to remap and inducing catastrophic cache misses. Consistent Hashing maps nodes and keys to an abstract 360-degree hash ring. When a server is added or removed, only \(1/N\) of keys are relocated, preventing cache thundering herds."

Q08 How do you calculate QPS and Peak QPS given Daily Active Users? Intermediate
Spoken Interview Answer

"First, multiply DAU by the average actions per user per day to get Total Daily Requests. Divide that by 86,400 seconds (rounded to \(10^5\) for mental math) to get Average QPS. To account for traffic spikes, peak hours, and diurnal usage curves, we typically multiply Average QPS by a factor of 2 to 3 to derive Peak QPS for infrastructure provisioning."

Q09 What is a Pull CDN vs a Push CDN and when do you use each? Intermediate
Spoken Interview Answer

"A Pull CDN (Origin Pull) fetches assets lazily from the origin server on the first user request and caches them at the edge until TTL expiration; it is the industry standard for web applications and blogs. A Push CDN requires the application or CI pipeline to upload all assets directly to CDN storage beforehand; it is ideal for massive static software updates or video releases."

Q10 What is SSL/TLS Termination at the Load Balancer level and what are its trade-offs? Intermediate
Spoken Interview Answer

"TLS termination decrypts incoming HTTPS traffic at the load balancer or reverse proxy, passing unencrypted HTTP requests to backend application servers across a private VPC network. It relieves application servers of CPU-intensive cryptographic handshakes and centralizes SSL certificate management, but requires trusting the internal network security boundary."

Q11 What is the difference between an Active-Passive and an Active-Active failover architecture? Intermediate
Spoken Interview Answer

"In Active-Passive, all traffic is handled by a primary instance while a secondary standby instance remains idle, replicating state. If the primary fails, a heartbeat detector triggers a failover to the standby. In Active-Active, two or more instances actively process requests in parallel; if one node fails, load balancers simply route 100% of traffic to the remaining healthy nodes with zero downtime."

Q12 What is the Least Connections algorithm and when does it outperform Round Robin? Intermediate
Spoken Interview Answer

"Least Connections tracks the active TCP or HTTP connections on each server and sends new requests to the instance with the lowest active load. It significantly outperforms Round Robin when requests have highly variable processing durations—such as large file uploads, complex analytical SQL queries, or persistent real-time WebSocket connections."

Q13 What are Liveness and Readiness probes in distributed systems? Intermediate
Spoken Interview Answer

"A Liveness probe checks if an application process is alive or deadlocked (e.g., event loop frozen); if it fails, the orchestrator restarts the container. A Readiness probe checks if the application is fully initialized and ready to receive traffic (e.g., database connection pool established, caches warmed); if it fails, load balancers temporarily stop routing traffic to it without restarting."

Q14 What is the order of magnitude latency difference between RAM and NVMe SSD access? Intermediate
Spoken Interview Answer

"RAM access takes approximately 100 nanoseconds, while sequential reads from an NVMe SSD take approximately 100 to 200 microseconds. This means RAM is roughly 1,000 to 2,000 times faster than the fastest SSDs, which is why caching frequently accessed data in Redis or memory is essential for high-throughput sub-10ms applications."

Q15 How does Anycast DNS routing work to deliver traffic to the nearest CDN Edge PoP? Advanced
Spoken Interview Answer

"Anycast assigns the exact same public IP address to hundreds of servers across diverse geographical data centers worldwide. Internet Service Providers use Border Gateway Protocol (BGP) routing tables to automatically direct client packets along the shortest network hop path, seamlessly routing each user to their nearest physical edge PoP without client configuration."

Q16 How do you invalidate cached assets across a distributed CDN at scale? Advanced
Spoken Interview Answer

"There are three primary strategies: 1) URL versioning/cache-busting (`app.a1b2c3.js`) with immutable `Cache-Control: max-age=31536000`, which requires zero invalidation API calls; 2) Surrogate-Key / Cache-Tags (associating responses with tags like `tag: product-42` and purging by tag via API); and 3) Explicit path purging, which is rate-limited and slower to propagate."

Q17 What is Virtual Node replication in Consistent Hashing and what problem does it solve? Advanced
Spoken Interview Answer

"With a small number of physical nodes, random hash placement creates non-uniform distribution across the ring (hot spots where one server owns 60% of the key space). Virtual Nodes assign 100–300 virtual tokens per physical node across the ring. This balances key distribution evenly and ensures load is shed uniformly when a node crashes."

Q18 What is the Thundering Herd problem in load balancing and reverse proxies? Advanced
Spoken Interview Answer

"A Thundering Herd occurs when hundreds of concurrent requests arrive simultaneously for a newly expired cache item. Instead of waiting for one thread to refresh the cache, all 500 requests bypass the cache and hammer the database simultaneously, causing connection exhaustion and CPU spikes. Reverse proxies solve this using request collapsing (`proxy_cache_use_stale updating`)."

Q19 How do you eliminate Single Points of Failure (SPOF) at the Load Balancer layer itself? Advanced
Spoken Interview Answer

"We pair load balancers in an Active-Passive high-availability cluster using VRRP (Virtual Router Redundancy Protocol) with Keepalived, sharing a floating virtual IP (VIP). If the active LB fails health checks, the passive LB claims the VIP within seconds. In cloud environments, managed LBs (like AWS ALB) automatically distribute across multiple availability zones under an Anycast DNS hostname."

Q20 How do you structure the trade-off conversation when choosing between consistency and availability? Intermediate
Spoken Interview Answer

"I frame it around domain business impact: for financial ledger systems or inventory checkout where double-spending creates catastrophic liability, Strong Consistency (CP) is mandatory even if transactions fail during network partitions. For social media feeds, likes, or analytics where momentary stale data is harmless, High Availability (AP) with eventual consistency provides far superior user experience."
