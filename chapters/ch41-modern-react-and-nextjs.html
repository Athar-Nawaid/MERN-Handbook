1. The Web Rendering Spectrum: CSR, SSR, SSG, and ISR

The modern web is not binary between "Single Page Application (SPA)" and "Server-Rendered Multi-Page Application (MPA)". Applications select rendering strategies on a per-route basis:

Rendering Strategy When HTML is Generated Strengths Trade-Offs & Bottlenecks
Client-Side Rendering (CSR) In the user's browser via JavaScript execution after downloading a blank HTML shell. Fast transitions after initial load; rich desktop-like app feel; zero backend server compute (served from S3/CDN). Slow First Contentful Paint (FCP); poor SEO for crawlers that don't execute JS; heavy bundle sizes on mobile devices.
Server-Side Rendering (SSR) On the backend server on every incoming HTTP request. Always up-to-date dynamic data; excellent SEO; fast initial content display for users. Higher server compute load; higher Time To First Byte (TTFB) because server must wait for database queries before sending HTML.
Static Site Generation (SSG) At application build time (e.g., next build). ⚡ Blazing fast: pre-rendered static HTML delivered from global edge CDNs; near-zero server infrastructure costs. Stale content: updating a blog post or price requires re-running the entire build and deployment pipeline.
Incremental Static Regeneration (ISR) At build time, then regenerated in the background on the edge after a configured revalidate TTL window. Combines the edge speed of SSG with the freshness of SSR without rebuilding the whole site. Eventual consistency: the first user visiting an expired page still sees stale data while background re-generation occurs.

2. React Server Components (RSC) Mental Model

Introduced in React 18 and championed by the Next.js App Router, React Server Components (RSC) represent the most significant paradigm shift in React since Hooks.

ASCII Diagram: React Server Components vs Client Bundle 
Traditional React (CSR/SSR):
All component code (even server-fetching logic) is bundled and downloaded to browser!
Client Bundle Size: 500 KB+ (Contains date-fns, markdown-parser, lodash, etc.)

React Server Components (RSC):
+-------------------------------------------------------------------------+
| SERVER BOUNDARY                                                         |
| - ServerComponent.tsx (directly queries database via Prisma / pg)       |
| - Heavy dependencies (marked, date-fns) stay 100% on the server!        |
| - Generates serialized "React Flight Data Stream" (JSON-like UI tree)    |
+-------------------------------------------------------------------------+
                                    |
                                    | (Streams Flight Tree: 0 KB JS overhead!)
                                    v
+-------------------------------------------------------------------------+
| BROWSER BOUNDARY (Client)                                               |
| - Only Client Components ('use client') ship JavaScript to the browser! |
| - Client merges Flight Tree into existing DOM without unmounting state   |
+-------------------------------------------------------------------------+

Key Properties of Server Components

  • Zero Client Bundle Size: Dependencies imported inside Server Components are never shipped to the client browser.
  • Direct Backend Resource Access: Server Components can directly read files from disk, access microservices via private VPC networks, and execute raw SQL queries with zero API endpoints.
  • No State or Effects: Because they execute once on the server, Server Components cannot use useState, useReducer, useEffect, or browser DOM APIs.

3. The 'use client' Boundary & Component Interleaving

A common misconception is that 'use client' means "this component only runs in the browser."

⚠️ The Reality of 'use client'

'use client' does not make a component client-only. Client Components are still pre-rendered to static HTML on the server during the initial page load (SSR)! The 'use client' directive simply defines a boundary where React packages that component and its dependencies into the client JavaScript bundle for browser interactivity and hydration.

Component Interleaving Rules

TypeScript: Interleaving Server and Client Components Cleanly 
// ❌ FORBIDDEN: You CANNOT directly import a Server Component into a Client Component!
'use client';
import ServerComponent from './ServerComponent'; // ERROR! Forces ServerComponent into client bundle!

export function ClientContainer() {
  return <div><ServerComponent /></div>;
}

// ✅ CLEAN PATTERN: Pass Server Component as children / slots into Client Component!
// ClientModal.tsx
'use client';
import { useState } from 'react';

export function ClientModal({ children }: { children: React.ReactNode }) {
  const [isOpen, setIsOpen] = useState(false);
  return (
    <div>
      <button onClick={() => setIsOpen(!isOpen)}>Toggle Modal</button>
      {isOpen && <div className="modal-content">{children}</div>}
    </div>
  );
}

// Page.tsx (Server Component)
import { ClientModal } from './ClientModal';
import { ServerDataWidget } from './ServerDataWidget';

export default async function Page() {
  return (
    <ClientModal>
      {/* ServerDataWidget executes 100% on the server, passed as children! */}
      <ServerDataWidget />
    </ClientModal>
  );
}

4. The Next.js App Router Architecture

Next.js uses a file-system based router in the app/ directory where folder structures define URL paths and special file conventions handle page lifecycles:

File Convention Role & Architectural Behavior
page.tsx Defines the unique UI content of a route. Makes a route publicly accessible.
layout.tsx Shared UI shell wrapping child routes (headers, sidebars). Preserves client component state across route navigations without re-rendering or unmounting.
loading.tsx Instant fallback UI (skeletons/spinners) wrapped automatically in a React Suspense Boundary while the page’s async data loads.
error.tsx Client-side React Error Boundary that isolates runtime errors in a route segment without crashing the entire layout. Must use 'use client'.
not-found.tsx UI rendered when the notFound() function is invoked or a route is invalid.

5. Streaming with React Suspense

In traditional SSR, page generation is blocked by the slowest database query. If a user profile takes 10ms to load but their analytics metrics take 2,000ms, the user stares at a blank screen for 2,000ms before receiving any HTML.

Streaming with Suspense breaks the page into independent asynchronous chunks. Next.js immediately sends the fast HTML layout and fallback skeletons, then streams in slow data chunks over HTTP chunked transfer encoding as promises resolve:

TypeScript: Streaming UI via Suspense Boundaries 
import { Suspense } from 'react';
import { UserProfileHeader } from './UserProfileHeader';
import { SlowAnalyticsDashboard } from './SlowAnalyticsDashboard';
import { SkeletonMetrics } from './SkeletonMetrics';

export default function DashboardPage() {
  return (
    <main className="dashboard-layout">
      {/* 1. Fast component renders and streams to client in 10ms */}
      <UserProfileHeader />

      {/* 2. Slow component wrapped in Suspense: Skeleton renders immediately */}
      <Suspense fallback={<SkeletonMetrics />}>
        {/* 3. When this async DB query finishes in 1.5s, HTML streams in to replace Skeleton! */}
        <SlowAnalyticsDashboard />
      </Suspense>
    </main>
  );
}

6. Server Actions & Form Mutations

Server Actions are asynchronous functions executed directly on the server, callable from client-side forms, buttons, or custom hooks without authoring custom REST API route handlers:

TypeScript: Production Server Action with Cache Revalidation 
'use server';

import { revalidatePath } from 'next/cache';
import { pool } from '@/lib/db';
import { z } from 'zod';

const CreateTodoSchema = z.object({
  title: z.string().min(3).max(100)
});

export async function createTodoAction(formData: FormData) {
  const rawTitle = formData.get('title');
  const validated = CreateTodoSchema.safeParse({ title: rawTitle });

  if (!validated.success) {
    return { error: 'Invalid todo title format' };
  }

  // Direct database query on the server!
  await pool.query('INSERT INTO todos (title, completed) VALUES ($1, false)', [
    validated.data.title
  ]);

  // Purge server cache and re-render the /todos route instantly
  revalidatePath('/todos');
}

7. Deconstructing Hydration Mismatch Errors

A Hydration Mismatch occurs when the pre-rendered HTML structure generated by the server does not exactly match the initial Virtual DOM tree generated by React in the browser during hydration.

Root Cause Code Anti-Pattern Remediation Strategy
Browser-Specific Globals <div>{typeof window !== 'undefined' ? 'Client' : 'Server'}</div> (Server renders 'Server', browser renders 'Client' \(\rightarrow\) Crash!). Use an isMounted state guard inside useEffect(), which only executes after hydration finishes.
Non-Deterministic Data <span>{new Date().toLocaleTimeString()}</span> (Server renders at 12:00:00; browser hydrates at 12:00:01 \(\rightarrow\) Mismatch!). Pass deterministic timestamps from the server as props, or render timestamps only inside client-mounted hooks.
Invalid HTML Structure Nesting a <div> inside a <p>, or omitting <tbody> inside a <table>. Browsers automatically repair invalid HTML by closing <p> tags early, creating an altered DOM that mismatches React’s Fiber tree. Strictly adhere to HTML spec nesting.

8. Practical Exercises

Exercise 1: Client Mounting Guard Hook against Hydration Mismatches

Scenario: Create a custom React hook useIsMounted() that guarantees a component only renders browser-dependent state (like localStorage or window dimensions) after initial hydration completes safely.

View Complete Solution
TypeScript Solution 
'use client';

import { useState, useEffect } from 'react';

export function useIsMounted(): boolean {
  const [mounted, setMounted] = useState(false);

  useEffect(() => {
    // useEffect executes strictly on the client AFTER initial hydration completes!
    setMounted(true);
  }, []);

  return mounted;
}

// Usage Example:
export function ThemeDisplay() {
  const isMounted = useIsMounted();
  if (!isMounted) {
    return <div className="skeleton-placeholder">Loading theme...</div>;
  }
  return <div>Active Theme: {localStorage.getItem('theme') || 'light'}</div>;
}

Exercise 2: Progressive Enhancement Form with Server Actions and useFormStatus

'use client';

import { useFormStatus } from 'react-dom';

export function SubmitButton({ label = 'Save' }: { label?: string }) {

9. Chapter-Specific Interview Questions & Answers

20 high-frequency interview questions covering React Server Components, Next.js App Router, rendering strategies, hydration mismatches, and Server Actions.

Q01 What is the difference between SSR, SSG, and ISR? Beginner
Spoken Interview Answer

"SSR (Server-Side Rendering) generates dynamic HTML on the server for every incoming request. SSG (Static Site Generation) pre-renders HTML once at build time, delivering fast edge CDN caching for static pages. ISR (Incremental Static Regeneration) serves static build pages from the edge, while regenerating them in the background as requests arrive after a configured revalidate time window."

Q02 What is a React Server Component (RSC)? Beginner
Spoken Interview Answer

"React Server Components are components that execute exclusively on the server and never ship their JavaScript code to the client browser. They can directly query databases or file systems, add zero kilobytes to the client bundle, and serialize their rendered output into a React Flight data stream that the browser merges into the DOM."

Q03 What does the 'use client' directive actually mean in Next.js? Beginner
Spoken Interview Answer

"`'use client'` does not mean client-only; Client Components are still pre-rendered to HTML on the server during the initial page load. It defines a boundary indicating that this component and its imported dependencies must be packaged into the client JavaScript bundle to enable React hooks (`useState`, `useEffect`) and browser event listeners (`onClick`)."

Q04 What is the difference between layout.tsx and template.tsx in Next.js? Beginner
Spoken Interview Answer

"`layout.tsx` persists across route transitions; it wraps child pages and preserves client component state and DOM elements without re-rendering or unmounting. `template.tsx` creates a new instance on every navigation, resetting state and re-running effects, which is useful for page entrance animations or route-change analytics logging."

Q05 What is a Server Action in Next.js? Beginner
Spoken Interview Answer

"A Server Action is an asynchronous function marked with `'use server'` that executes directly on the backend server. It can be called from client forms or button event handlers without creating manual API endpoints, supporting Progressive Enhancement where forms can submit even before client JavaScript has finished downloading."

Q06 What causes a React Hydration Mismatch error and how do you resolve it? Intermediate
Spoken Interview Answer

"Hydration errors occur when the server-rendered HTML doesn't match the client's initial Virtual DOM tree. Common causes include accessing `window` or `localStorage` during initial render, non-deterministic values like `Date.now()`, or invalid HTML nesting (like `

` inside `

`). Fixes include deferring client-only logic to `useEffect()` or using `suppressHydrationWarning`."

Q07 How does UI Streaming with Suspense improve perceived performance? Intermediate
Spoken Interview Answer

"In traditional SSR, page transmission is blocked by the slowest database query. Streaming with Suspense allows the server to send the fast layout shell immediately alongside loading skeletons. As slow asynchronous data components resolve, the server streams the remaining HTML chunks over the existing HTTP connection, drastically cutting Time to First Byte (TTFB)."

Q08 Can a Client Component import a Server Component directly? Intermediate
Spoken Interview Answer

"No. Importing a Server Component into a Client Component forces the server component to be compiled into the client bundle, causing build errors if it uses server-only APIs. However, you can pass a Server Component as a child or prop (`children`) into a Client Component, allowing the Server Component to execute on the server while the Client Component manages the outer UI shell."

Q09 What is the difference between revalidatePath and revalidateTag in Next.js? Intermediate
Spoken Interview Answer

"`revalidatePath('/products')` purges the cached static or server data associated with a specific URL route path. `revalidateTag('collection-42')` purges cache entries across any route that tagged its fetch requests with that identifier, allowing targeted cache invalidation across multiple disparate pages in a single call."

Q10 What is the React Flight Data Stream? Intermediate
Spoken Interview Answer

"The Flight Data Stream is React's compact, binary-like serialized representation of a rendered Server Component tree. It describes the virtual DOM nodes, props, and 'slots' where Client Components should mount. When navigating between routes, Next.js streams this Flight tree, allowing the browser to update the UI without re-fetching full HTML or losing client state."

Q11 How do Route Groups work in the Next.js App Router? Intermediate
Spoken Interview Answer

"Route groups are directories wrapped in parentheses, like `app/(marketing)/about` and `app/(dashboard)/settings`. They organize routes into logical sections and allow applying different root layouts to different sections of the application without affecting the public URL path (e.g., the URL is `/about`, not `/(marketing)/about`)."

Q12 What is the purpose of generateStaticParams in Next.js? Intermediate
Spoken Interview Answer

"`generateStaticParams` is used in dynamic routes (`[slug]`) to define the exact list of route parameters to pre-render statically at build time (replacing `getStaticPaths` from the Pages router). During `next build`, Next.js executes this function and generates static HTML files for all returned parameter combinations."

Q13 How does error.tsx handle runtime errors in the Next.js App Router? Intermediate
Spoken Interview Answer

"`error.tsx` automatically wraps the route segment and its children in a React Error Boundary. If an error occurs during rendering or data fetching, it catches the exception and renders fallback error UI with a `reset()` function, isolating the failure to that specific sub-route without crashing the parent layout or navigation bar."

Q14 What is Progressive Enhancement with Server Actions? Intermediate
Spoken Interview Answer

"When a Server Action is passed to a `

`, the form functions as a standard HTML form submission even if JavaScript has failed to download or is disabled by the user. When JavaScript is enabled, React intercepts the form submission, sending an asynchronous fetch request with seamless client-side state updates."

Q15 What is the Server-Only package in Next.js and why should you use it? Advanced
Spoken Interview Answer

"The `server-only` package throws a build-time compile error if a module containing private server code (like database clients or secret API keys) is accidentally imported into a Client Component. Adding `import 'server-only'` at the top of utility files prevents catastrophic data and credential leaks into client bundles."

Q16 How does Request Deduplication work across Server Components in Next.js? Advanced
Spoken Interview Answer

"Next.js extends the native `fetch` API to automatically memoize HTTP requests with identical URLs and options during a single server render pass. If three separate Server Components in the tree call `fetch('https://api.com/user/me')`, the network request executes exactly once, eliminating prop-drilling or Context wrappers for server data."

Q17 What are Parallel Routes and Intercepting Routes in Next.js? Advanced
Spoken Interview Answer

"Parallel Routes (`@slot`) allow simultaneously rendering multiple independent pages within the same layout (like dashboard panels). Intercepting Routes (`(.)photo/[id]`) allow loading a route within the current layout context (e.g., displaying a photo modal over a feed on client clicks) while preserving direct URL shareability that displays the full photo page on refresh."

Q18 Why can't you pass functions as props from Server Components to Client Components? Advanced
Spoken Interview Answer

"Props passed across the Server-to-Client boundary must be serializable into the React Flight data stream (JSON primitives, plain objects, arrays). JavaScript functions, class instances, or database connections cannot be serialized across a network stream. The exception is Server Actions, which are converted into unique cryptographic endpoint references."

Q19 What is Partial Prerendering (PPR) in Next.js? Advanced
Spoken Interview Answer

"Partial Prerendering combines static and dynamic rendering in a single HTTP response. The static outer shell (layouts, static text) is pre-rendered at build time and served immediately from the edge CDN, while dynamic holes wrapped in Suspense boundaries are streamed concurrently from the server, giving the speed of SSG with the dynamism of SSR."

Q20 How do you explain the transition from Pages router to App router to team stakeholders? Intermediate
Spoken Interview Answer

"The Pages router shipped monolithic client bundles where all page code ran in the browser. The App router embraces Server Components, which slashes client bundle sizes by 40–60%, eliminates redundant API endpoints through direct database access, and improves perceived page load times through progressive UI streaming with Suspense."
